Arquitectura y flujo de datos

Tres piezas desplegadas por separado — frontend estático, API con estado, base de datos — y un punto fijo: ningún hallazgo generado por IA llega a la empresa sin que un consultor lo revise.

El frontend (React) se publica como archivos estáticos en GitHub Pages: no corre nada del lado del servidor, solo le habla a la API por HTTPS. La API (FastAPI, en un contenedor Docker sobre Render) es la única pieza con lógica y la única que toca la base de datos (Postgres en Neon). Separarlas así significa que el sitio nunca se cae por un despliegue del backend, y que el proveedor de IA se puede cambiar sin tocar el frontend ni la lógica de negocio.

01 Cómo viaja una petición

Toda petición pasa por el mismo embudo: el token decide quién es, las variables de sesión de Postgres deciden qué puede ver (aislamiento por empresa vía Row-Level Security), y solo si la ruta lo necesita se desvía hacia la capa de IA — intercambiable por variable de entorno y trazada en LangSmith sin que el resto del código lo sepa.

02 El punto de control humano

El agente nunca publica directo. Genera candidatos — hallazgos, puntajes, recomendaciones — que quedan en un estado intermedio invisible para la empresa hasta que un consultor decide, bloque por bloque, si se acepta, se edita o se rechaza. Solo entonces se habilita el botón de publicar.

03 Pila técnica

Frontend

  • React + TypeScript, build con Vite
  • Estático en GitHub Pages, sin servidor propio
  • Modo demo: intercepta fetch con datos de ejemplo si no hay backend

Backend

  • FastAPI en Docker, desplegado en Render
  • Auth con JWT + argon2; roles company_user / consultant
  • Extracción: pypdf, python-docx; export: reportlab

Datos

  • Postgres gestionado en Neon
  • Aislamiento por empresa con Row-Level Security
  • Rol ruta_app sin permisos de dueño — mínimo privilegio

IA y trazabilidad

  • Groq, OpenAI o Anthropic tras una sola interfaz
  • LangSmith traza cada llamada automáticamente
  • Ninguna evidencia se acepta sin cita verificada en la fuente

Cada pieza se despliega y versiona por separado: un cambio de proveedor de IA es una variable de entorno en Render, no un redeploy del frontend; un ajuste visual es un push a GitHub Pages que no toca el backend ni la base de datos.
